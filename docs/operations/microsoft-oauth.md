# Ящики Microsoft (Outlook, Microsoft 365)

Как MailExpert подключает ящики Microsoft по OAuth и что нужно от регистрации приложения в Entra.
Это необязательный путь только для администратора: ящики, с которыми работает команда, подключаются
автоматически (ящики почтового узла — через EOP, Gmail — через Google-приложения), и пользователям
переподключать ящики Microsoft не нужно. Настройка клиента (Client ID, Tenant ID, секрет, Redirect
URI) и подключение — в панели администратора: «Настройки → Интеграции → Microsoft 365 / Outlook.com».

## Адрес ящика и привязка

- Адрес ящика берётся только из проверенных утверждений ID-токена: `email` при `xms_edov = true`
  или `upn` участника тенанта (без `#EXT#`). `verified_primary_email` принимается только тогда, когда
  Tenant ID указывает одну организацию (не `common`, `organizations`, `consumers`). `preferred_username`
  и `email` без `xms_edov` не принимаются: вход отклоняется с `email_not_verified`.
- Поэтому в регистрации приложения нужны необязательные утверждения ID-токена: Token configuration →
  Add optional claim → ID → `email`, `xms_edov`, `upn`.
- Для личных учётных записей (Outlook.com, Hotmail) документация Microsoft не говорит, когда
  приходит `xms_edov`. Перед тем как полагаться на личные учётные записи, проверьте пробным входом,
  что ящик подключается.
- Ящик привязан к учётной записи Microsoft по `tid` + `oid` (поле `oauth_subject`). Добавление
  никогда не трогает существующий ящик с тем же адресом; переподключение обновляет только свой
  ящик Microsoft и только для той же учётной записи. Ящики почтового узла, Gmail и ящики с паролем
  OAuth не меняет.
- Ящик, подключённый до появления привязки (`oauth_subject` пуст), привязывается при первом
  переподключении с проверенным адресом этого ящика.
- Если учётную запись владельца пересоздали или ящик привязан не к той записи, администратор
  нажимает «Сбросить привязку OAuth» у ящика в «Настройки → Аккаунты» (так же для Gmail). Действие
  записывается в журнал (`mailbox.oauth_subject_reset`); следующее переподключение привяжет ту
  учётную запись, которая войдёт с проверенным адресом ящика.

## Вход по коду устройства

- Если Redirect URI не задан, работает только вход по коду устройства; его запускает администратор
  в «Интеграциях» (там же, если ящику Microsoft понадобится новый вход).
- Код устройства можно выманить: тот, кому пользователь передаст свой код, подключит на его место
  свою учётную запись Microsoft, а присланный пользователю чужой код заставит его подключить свою
  учётную запись к чужому сеансу. Панель предупреждает об этом рядом с кодом. Если вход по коду не
  нужен, не включайте Allow public client flows в регистрации приложения.
