# Google-приложения для ящиков Gmail

Как администратор настраивает OAuth-приложения Google, через которые MailExpert подключает личные ящики `@gmail.com`, и что делать при сбоях. Дизайн — [2026-09-15-google-multi-app-design.md](../superpowers/specs/2026-09-15-google-multi-app-design.md) и раздел «Уточнения, принятые при реализации PR 8» в [2026-09-15-shared-mailboxes-google-login-design.md](../superpowers/specs/2026-09-15-shared-mailboxes-google-login-design.md).

В документе только заглушки: `<APP_HOST>` — основной адрес из `APP_URL`, `<ALT_HOST>` — дополнительный из `APP_ALT_URLS`, `<DEV_HOST>` — адрес стенда разработки.

OAuth-клиент для входа в сам MailExpert (`AUTH_GOOGLE_CLIENT_ID`, scope `openid email`) — отдельная вещь и здесь не описан; его redirect URI — `<origin>/oauth/login/google/callback`.

## Почему приложений несколько

Приложение Google без верификации со scope `https://mail.google.com/` принимает не больше 100 уникальных пользователей за всё время жизни проекта Google Cloud. Счёт не уменьшается: удаление ящика, отзыв доступа и удаление OAuth-клиента место не возвращают.

Решение владельца — верификацию и CASA не проходить. Поэтому ящики распределяются по нескольким приложениям:

- одно приложение MailExpert = один проект Google Cloud = один OAuth-клиент;
- MailExpert сам выбирает приложение для каждого адреса и считает занятые места;
- **два клиента из одного проекта не дают новых мест**: они делят один лимит. MailExpert отклоняет второй клиент того же проекта (`app_same_project`) по номеру проекта — числу в начале client ID.

## Проекты для разработки и прода

Проекты разработки и прода не смешиваются: тестовые подключения со стенда разработки тратят места проекта навсегда.

- **Прод** — проекты только для рабочей установки, redirect URI только рабочих хостов.
- **Разработка** — свой проект (или несколько) с redirect URI `<DEV_HOST>`, например `http://localhost:<port>/oauth/google/callback`. Режим Testing допустим только здесь, с тестовыми пользователями, внесёнными в консоль вручную, и с учётом того, что доступ в нём истекает через 7 дней.

## Создание проекта Google Cloud

Для каждого приложения:

1. Создайте новый проект Google Cloud. Не используйте проект, где уже есть OAuth-клиент для MailExpert.
2. Экран согласия OAuth (Google Auth Platform → Branding / Audience):
   - аудитория **External** — ящики личные `@gmail.com`, режим Internal для них неприменим;
   - статус публикации **In Production** (Publish app). Верификацию не запускайте. В режиме **Testing** доступ истекает через 7 дней и тестовых пользователей нужно вносить вручную — для рабочей установки не подходит.
3. Data Access → scopes: `openid`, `email`, `profile`, `https://mail.google.com/`. Больше ничего: MailExpert запрашивает ровно этот набор. `https://mail.google.com/` — restricted scope; он нужен, потому что MailExpert читает почту по IMAP, а отправляет через Gmail API (по умолчанию) или SMTP, и оба принимают OAuth-токен только с этим scope. Если scope нет в списке, включите Gmail API (APIs & Services → Library) или добавьте scope вручную.
4. APIs & Services → Library → найдите **Gmail API** → **Enable** (или `gcloud services enable gmail.googleapis.com --project=<project-id>`). Без этого шага MailExpert отправляет письма этого приложения через SMTP автоматически (см. «Отправка почты» ниже) — панель работает, но теряет смысл запасного пути через Gmail API.
5. Clients → Create client → **Web application**. В Authorized redirect URIs добавьте callback каждого публичного хоста (см. ниже). Без wildcard: Google сверяет адрес целиком.
6. Скопируйте client ID и client secret и добавьте приложение в MailExpert.

## Callback-адрес

Экран: **Настройки → Интеграции → Почтовые провайдеры → «Google-приложения»** (только администратор).

- Callback общий для всех приложений: `https://<APP_HOST>/oauth/google/callback`. Экран подставляет адрес открытой страницы; нажмите «Сохранить» до добавления приложений. Пока callback не сохранён, подключение Gmail отвечает `not_configured`. Экран и сервер принимают только адрес `http(s)` с путём ровно `/oauth/google/callback`, без `?` и `#` (`redirect_uri_invalid` иначе): другой путь вернул бы браузер на страницу, которая подключение не завершает.
- Из сохранённого адреса берётся только путь. Хост берётся из запроса, если он есть в `APP_URL` или `APP_ALT_URLS`: подключение, начатое на `<ALT_HOST>`, возвращается на `https://<ALT_HOST>/oauth/google/callback`. Сессия привязана к хосту, поэтому возврат на другой хост закончился бы `invalid_state`.
- Поэтому в **каждом** OAuth-клиенте регистрируется по одному redirect URI на каждый публичный хост:
  - `https://<APP_HOST>/oauth/google/callback`
  - `https://<ALT_HOST>/oauth/google/callback`
- Если панель открыта через другой хост, экран показывает подсказку с callback этого хоста.
- Запрос с хоста, которого нет в `APP_URL`/`APP_ALT_URLS`, получает сохранённый callback как есть.

Переменная `GOOGLE_REDIRECT_URI` — запасной вариант, если callback ни разу не сохраняли на экране: сохранённый callback имеет приоритет, без него backend берёт значение переменной, с которым стартовал. `docker-compose.yml` передаёт в контейнер backend `GOOGLE_REDIRECT_URI`.

## Добавление приложения в MailExpert

«Добавить приложение» на экране «Google-приложения» — либо импортом JSON-файла клиента, либо
вводом полей вручную (как раньше). Оба пути ведут к одному и тому же приложению; поле «Лимит
пользователей» — общее для обоих, по умолчанию 100.

### Импорт JSON-файла

В Google Cloud Console: **Credentials → OAuth client → Create client → Web application**, затем
у уже созданного клиента — **Download JSON**. Файл называется
`client_secret_<id>.apps.googleusercontent.com.json`.

- На экране — кнопка «Импортировать JSON-файл» или перетащите файл на форму.
- Название по умолчанию берётся из `project_id` файла; отредактируйте, если нужно другое.
- Идентификатор клиента показывается после импорта, секрет клиента не показывается никогда —
  ни в форме, ни в ответе API.
- Принимается только клиент типа **Web application**. Десктопный (installed) клиент и ключ
  сервисного аккаунта (`"type": "service_account"`) отклоняются с понятной причиной: у них нет
  секрета, пригодного для серверного redirect-потока, который использует MailExpert.
- Если `redirect_uris` файла не содержат текущий callback-адрес панели (см. «Callback-адрес»
  выше), экран показывает предупреждение с этим адресом — добавьте его в Authorized redirect URIs
  клиента в консоли. Если сам callback ещё не сохранён на экране, предупреждение об этом отдельное.
  Приложение при этом всё равно создаётся: предупреждение не блокирует сохранение.

### Ввод вручную

| Поле | Что вводить |
| --- | --- |
| Название | Любое, до 100 символов, например «Google 3». |
| Идентификатор клиента | `<число>-<строка>.apps.googleusercontent.com`. После создания не меняется: другой client ID — другое приложение. |
| Секрет клиента | Хранится зашифрованным, API его не возвращает. |
| Лимит пользователей | По умолчанию 100. Уменьшите, если проектом уже пользовались до MailExpert: Google считает и тех пользователей. Лимит ниже текущего числа занятых мест сразу делает приложение заполненным. |

Ошибки: `client_id_invalid` — не похоже на client ID Google; `app_exists` — этот client ID уже
добавлен; `app_same_project` — клиент из этого проекта уже добавлен; `client_json_invalid` — файл
не JSON или не файл OAuth-клиента; `client_json_service_account` — это ключ сервисного аккаунта;
`client_json_not_web` — это десктопный (installed) клиент; `client_json_incomplete` — в файле нет
идентификатора или секрета клиента; `client_json_conflict` — указаны одновременно и файл, и
идентификатор/секрет вручную.

### Добавление из командной строки

Для установленной панели, без браузера — скрипт на хосте, рядом с `backup.sh` и `update.sh`:

```bash
sudo /opt/mailexpert/app/scripts/deploy/google-app.sh add client_secret_<id>.apps.googleusercontent.com.json \
  [--label "Google 3"] [--user-limit 100]
sudo /opt/mailexpert/app/scripts/deploy/google-app.sh list
```

Файл читается с хоста и передаётся в контейнер backend через
`docker compose ... exec -T backend node src/cli/googleApp.js add < файл` — секрет клиента не
попадает ни в аргументы команды, ни в историю шелла, ни в список процессов. `--label` без значения
по умолчанию берётся из `project_id` файла, `--user-limit` — 100, как и на экране. Ошибки и
предупреждение о redirect URI печатаются в консоль теми же кодами, что и на экране; скрипт
завершается ненулевым кодом при ошибке.

Если до перехода на несколько приложений был настроен один клиент (старая карточка Google в Настройках → Интеграции), он при старте один раз импортируется как «Google 1» со всеми существующими Google-ящиками. После появления первого приложения импорт больше не выполняется, и это сохраняется в базе: приложение, удалённое на экране, не вернётся при следующем запуске. Переменные окружения `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` не читаются: приложения Google ведутся только на экране «Приложения Google».

## Места

**Занято = журнал + брони.**

- Журнал (`google_oauth_grants`) — адреса, которым приложение хоть раз выдало токен. Запись появляется сразу после проверки ID token на callback, в том числе если подключение дальше отклонено: Google уже засчитал пользователя.
- Бронь ставится при старте подключения нового адреса и живёт до конца OAuth state (10 минут). Каждый старт ставит свою бронь; повторный старт того же адреса остаётся в том же приложении и второго места не занимает: место считается по адресу. Callback при любом исходе снимает только бронь своего старта, поэтому неудачный callback одной вкладки не освобождает место, пока другой старт того же адреса ещё идёт. Истёкшие брони удаляются при каждом подсчёте.
- Колонка «Занято / лимит» показывает эту сумму. Во время подключения один адрес может недолго считаться дважды (бронь и запись журнала) — это намеренный запас.
- **Места не возвращаются.** Удаление ящика, отзыв доступа и удаление приложения журнал не трогают: журнал ведётся по проекту Google Cloud (номер проекта из client ID), а не по записи приложения.
- Адрес, который уже есть в журнале приложения `active` или `closed`, подключается повторно через это же приложение и нового места не тратит.

## Состояния приложения

| Состояние | Новые адреса | Привязанные ящики |
| --- | --- | --- |
| Активно (`active`) | принимает, пока есть место | работают |
| Закрыто (`closed`) | не принимает | работают; переподключаются через это приложение; адреса из его журнала возвращаются в него без нового места |
| Отключено (`disabled`) | не принимает | сразу переводятся в «нужно переподключить», IMAP-соединения закрываются; переподключение идёт через другое приложение |

**«Заполнено»** — не отдельное состояние, а признак активного приложения, у которого занято ≥ лимита. Новые адреса идут в следующее по дате создания активное приложение с местом. Когда места нет нигде, вариант Gmail в «Добавить аккаунт» остаётся доступным с пометкой, что добавить можно только адрес, который уже подключался: такой адрес возвращается в приложение из своего журнала без нового места, даже если оно заполнено или закрыто. Для нового адреса старт отвечает `no_app_capacity`. Без настроенных приложений вариант неактивен.

Как MailExpert выбирает приложение для адреса:

1. Переподключение ящика — его приложение, если оно `active` или `closed`.
2. Иначе самое раннее приложение `active` или `closed`, в журнале которого есть этот адрес.
3. Иначе первое по дате создания `active`-приложение со свободным местом; на адрес ставится бронь.
4. Иначе `no_app_capacity`, а если приложений нет или все отключены — `not_configured`.

«Закрыть для новых ящиков» — для проекта, в котором Google, возможно, насчитал больше пользователей, чем видит MailExpert, или который скоро заполнится. «Отключить» — только когда ящики должны уйти из проекта (см. ниже). Возврат из «Отключено» в другое состояние флаг «нужно переподключить» с ящиков не снимает.

## Как пользователь добавляет Gmail

1. «Добавить аккаунт» — в меню пользователя слева над «Настройками» или во вкладке «Аккаунты» — вариант «Личный Gmail» (он выбран по умолчанию).
2. Пользователь вводит адрес. Подсказка под полем показывает ящики установки («Уже подключено», «Нужно переподключить» с кнопкой, «Отключён в настройках») и адреса, подключавшиеся раньше и удалённые («Подключался раньше»).
3. «Продолжить через Google». Сервер проверяет, что такого ящика в установке ещё нет, выбирает приложение и открывает вкладку Google. Адрес уходит в Google подсказкой `login_hint` и не попадает в URL MailExpert. Если браузер не открыл вкладку, форма показывает ссылку «Открыть страницу Google»: она одноразовая и действует минуту.
4. На странице Google пользователь входит в аккаунт (если браузер ещё не вошёл), проходит экран «Приложение не проверено» и даёт согласие.
5. После возврата ящик появляется у всех пользователей установки. Если второе имя отправителя из формы совпало с основным (или, без основного, с именем профиля Google), второе имя не сохраняется, и панель говорит об этом отдельным уведомлением.

### Экран «Приложение не проверено»

Google показывает его, потому что приложение не верифицировано, при каждом согласии — MailExpert всегда запрашивает согласие заново (`prompt=consent`), поэтому и при переподключении. Пользователь нажимает «Дополнительные настройки» (Advanced) и «Перейти на страницу …» с названием приложения. Предупредите сотрудников заранее, иначе они отменят вход (`access_denied`).

На экране согласия у Gmail есть отдельная галочка доступа к почте. Если её снять, подключение закончится `scope_missing`.

### Переподключение

Когда токен отозван, истёк или приложение отключено, ящик получает состояние «нужно переподключить». Кнопка «Переподключить» — у ящика в списке слева, в его контекстном меню и во вкладке «Аккаунты». Переподключение доступно любому вошедшему пользователю; в Google нужно войти в тот же аккаунт Gmail. Уже подключённый адрес через «Добавить аккаунт» повторно не добавляется.

Если ящик попал в «нужно переподключить» из-за того, что Google отклонил его refresh token, переподключение сохраняет только новый refresh token. Ответ Google без него заканчивается `missing_refresh_token`, а ящик остаётся в «нужно переподключить»: прежний токен уже недействителен.

## Ошибки подключения

Ошибки старта показываются в форме без открытия Google:

| Код | Причина | Что делать |
| --- | --- | --- |
| `email_invalid` | Адрес введён не целиком. | Ввести адрес полностью. |
| `already_connected` | Ящик с этим адресом уже есть в установке. | Если он требует переподключения — «Переподключить». |
| `no_app_capacity` | Ни в одном активном приложении нет места. | Администратор добавляет новое приложение. |
| `not_configured` | См. ниже. | См. ниже. |

Коды после возврата из Google (уведомление «Google / Gmail»):

| Код | Причина | Что делать |
| --- | --- | --- |
| `access_denied` | Пользователь отменил вход или согласие. Тот же код Google возвращает, если проект заблокирован или сам отказал по лимиту. | Повторить, пройдя экран «Приложение не проверено». Если отказ повторяется без отмены — администратор закрывает или отключает приложение и проверяет проект в консоли. |
| `invalid_state` | Ссылка истекла (больше 10 минут), уже использована, открыта в другой сессии или вернулась на другой хост; ящик для переподключения не найден. | Начать заново с того же хоста. Если повторяется на `<ALT_HOST>` — проверить `APP_ALT_URLS` и redirect URI этого хоста. |
| `not_configured` | Приложений нет или все отключены; callback не сохранён; приложение удалено или отключено во время подключения; секрет не расшифровывается (сменился `ENCRYPTION_KEY`). | Сохранить callback, добавить или включить приложение, заново ввести секрет. |
| `account_mismatch` | В Google выбран другой аккаунт, чем введённый адрес, или аккаунт Google с этим адресом не тот, что был у ящика (`sub` не совпадает). | Повторить и выбрать нужный аккаунт. Место в журнале для выбранного по ошибке аккаунта уже занято. |
| `scope_missing` | Не выдан доступ к Gmail (снята галочка). | Повторить и оставить доступ к Gmail. |
| `missing_refresh_token` | Google не выдал офлайн-доступ: при добавлении, при переносе ящика в другое приложение или при переподключении ящика, чей прежний токен Google уже отклонил. | Пользователь удаляет приложение в разрешениях аккаунта Google и подключается заново. |
| `email_not_verified` | Google не подтвердил адрес аккаунта. | Подключить другой аккаунт. |
| `already_connected` | Ящик с этим адресом появился, пока шёл вход. | Ничего: ящик уже подключён. |
| `no_app_capacity` | При переподключении нет ни своего, ни свободного приложения. | Добавить приложение. |
| `authentication_failed` | Обмен кода не удался: неверный секрет клиента, сбой сети или ответ Google без токена. | Повторить; при повторе — проверить секрет в MailExpert и в консоли. |

Если redirect URI хоста не зарегистрирован в клиенте, Google показывает свою ошибку `redirect_uri_mismatch` и в MailExpert не возвращается.

Когда подключение отклонено после выдачи токена, MailExpert токены не сохраняет и отзывает новый токен. Отзыв пропускается, если в этом приложении уже есть рабочий ящик с тем же адресом: Google отзывает доступ человека ко всему проекту, и рабочий ящик отключился бы тоже.

## Отключение приложения и перенос ящиков

Порядок, когда ящики должны уйти из проекта (блокировка, ошибка при создании, нужен другой проект):

1. Убедитесь, что есть другое активное приложение со свободными местами на все переносимые адреса, либо добавьте его.
2. «Отключить» у старого приложения. Подтверждение называет число ящиков. Все его ящики сразу получают «нужно переподключить», IMAP-соединения закрываются, обновление токенов для них прекращается.
3. Каждый владелец ящика проходит «Переподключить». Ящик уходит в приложение, в журнале которого уже есть его адрес, иначе в первое активное со свободным местом — это тратит место. Письма и настройки ящика в MailExpert сохраняются. Старый токен отзывается после переноса (без гарантии: для заблокированного проекта отзыв может не пройти, это не ошибка).
4. Число «Ящиков» у отключённого приложения падает по мере переподключения. Удалить приложение можно, только когда оно дойдёт до нуля (`app_in_use` иначе).

Удаление приложения журнал не удаляет: он принадлежит проекту Google Cloud. Если снова добавить клиент того же проекта (тот же или новый client ID), приложение сразу показывает уже занятые места, а адреса из журнала возвращаются в него без нового места. Пока приложения этого проекта нет, его адреса не предлагаются как «Подключался раньше». Журналы приложений, удалённых до этого обновления, не восстанавливаются: для такого проекта выставьте лимит с учётом уже занятых мест.

## Ротация client secret

Refresh token привязан к OAuth-клиенту, а не к секрету, поэтому смена секрета сохраняет подключённые ящики.

1. В консоли Google Cloud у клиента добавьте новый секрет, старый пока не отключайте.
2. В MailExpert «Изменить» у приложения, вставьте новый секрет, сохраните. Пустое поле сохраняет прежний секрет.
3. Проверьте, что ящики этого приложения синхронизируются, и отключите и удалите старый секрет в консоли.

Если в MailExpert окажется неверный секрет, обновление токенов падает временной ошибкой и повторяется: ящики не переводятся в «нужно переподключить» и восстанавливаются после исправления секрета. Новые подключения в это время заканчиваются `authentication_failed`.

## Удаление ящика и отзыв доступа

- Удаление ящика в MailExpert (любой вошедший пользователь) удаляет ящик, его письма и папки у всех пользователей. Запись `mailbox.deleted` в журнале действий остаётся с адресом ящика.
- MailExpert при удалении отзывает токен ящика в Google (без гарантии: сбой отзыва удаление не останавливает) и удаляет ящик только после ответа Google, не дольше 10 секунд. Google отзывает доступ человека ко всему проекту, поэтому поздний отзыв отключил бы и тот же адрес, добавленный заново сразу после удаления; пока ящик не удалён, повторное добавление адреса отвечает `already_connected`. Если отзыв не прошёл, владелец аккаунта удаляет приложение в разрешениях своего аккаунта Google (сторонние приложения и сервисы).
- Место не возвращается. Адрес остаётся в журнале приложения и виден в подсказке «Подключался раньше», пока приложение не удалено. Повторное подключение этого адреса нового места не тратит, пока приложение `active` или `closed`.
- Если владелец отозвал доступ в Google, а ящик в MailExpert остался, при следующем обновлении токена ящик получает «нужно переподключить».

## Отправка почты: Gmail API и запасной SMTP

По умолчанию MailExpert отправляет письма Gmail-ящика через Gmail API (HTTPS,
`gmail.googleapis.com:443`), а не через SMTP (`smtp.gmail.com:465/587`). Причина —
некоторые сети (в том числе хостинги, закрывающие исходящие почтовые порты) блокируют
`smtp.gmail.com`, оставляя `gmail.googleapis.com:443` доступным: тот же HTTPS-порт, что и у
самой панели. На все остальные ящики (mailcow, обычный IMAP/SMTP, Microsoft, Yahoo) это не
влияет — они всегда отправляют через SMTP, как раньше.

- **Запасной путь.** Если API отправить письмо определённо не смог — Gmail API отключён в
  проекте (см. шаг 4 выше), сеть недоступна ещё до отправки запроса, либо Google ответил 429
  из-за обычного троттлинга запросов (не дневного лимита отправки, см. ниже) ещё до подтверждения
  приёма, — MailExpert отправляет то же письмо через SMTP в рамках того же запроса пользователя,
  без повторного щелчка «Отправить» и без дубликата.
- **5xx от Google** запасным путём не считается: неизвестно, принял ли Google письмо перед
  сбоем, а повтор через SMTP мог бы отправить его дважды. Это тот же «неопределённый исход», что
  и ниже.
- **Неопределённый исход** (5xx от Google, или соединение оборвалось уже после отправки запроса)
  на SMTP не переключается: письмо могло уйти, и повторная отправка удвоила бы его. Пользователь
  видит то же предупреждение «Соединение с почтовым сервером оборвалось во время отправки», что и
  при похожем сбое SMTP — проверьте «Отправленные» перед повтором.
- **Дневной лимит отправки Gmail** (500 писем/сутки для обычных ящиков, больше для Workspace) —
  окончательный отказ что через API, что через SMTP: одна и та же стенка почтового сервера
  Gmail, запасной путь не поможет. Пользователь видит понятное сообщение и не может отправить,
  пока лимит не сбросится.
- **Отозванный или урезанный доступ.** 401, переживший принудительное обновление токена, и 403
  `insufficientPermissions`/`ACCESS_TOKEN_SCOPE_INSUFFICIENT` (в проекте сузили scope согласия)
  переводят ящик в «нужно переподключить» тем же способом, что и отказ обновления токена
  (`oauth_reconnect_required`) — не только сообщением пользователю.
- **Gmail API отключён в проекте.** Карточка приложения на экране «Google-приложения» показывает
  предупреждение «Gmail API отключён в этом проекте Google Cloud: почта уходит через SMTP.
  Включите Gmail API в проекте» — до первой же успешной отправки через API после включения, когда
  предупреждение само пропадает. При `GMAIL_SEND_TRANSPORT=smtp` это предупреждение снимается
  само: раз API не пробуется, «отключён» ему не поставить в вину.
- **`GMAIL_SEND_TRANSPORT`** (переменная окружения backend, `docker-compose.yml` передаёт её в
  контейнер): `api` (по умолчанию) или `smtp` — всегда SMTP для Gmail, как и для остальных
  провайдеров. Неизвестное значение равносильно `api` с предупреждением в логе backend при старте.
- **Тема письма и Message-ID.** При ответе в переписке, если у исходного письма известен
  Gmail-тред (`X-GM-THRID`, хранится как `provider_thread_id`), отправка через API продолжает тот
  же тред; иначе, как и раньше, тред определяется по `In-Reply-To`/`References`. Устаревший
  `threadId` (письмо давно перемещено/удалено на стороне Google) не проваливает отправку: панель
  повторяет тот же запрос без `threadId`. Свой `Message-ID` MailExpert передаёт в самом письме, и
  Gmail его сохраняет — сверка «Отправленных» по `Message-ID` работает как прежде для обоих путей.

## Риски

- **Правила Google.** Google может ограничить или заблокировать проекты, распределяющие пользователей сверх лимита неверифицированного приложения: условия Google APIs запрещают обходить документированные ограничения. При блокировке все ящики проекта теряют доступ. Перенос в другое приложение сохраняет данные в MailExpert, но требует входа каждого затронутого сотрудника.
- **Расхождение счёта с Google.** Google может засчитать пользователей, которых MailExpert не видел: использование проекта до MailExpert, прерванные попытки. Смягчение — лимит меньше 100 и состояние «Закрыто» заранее.
- **Отзыв не возвращает место** и может не пройти для заблокированного проекта; это не ошибка.
- **Экран «Приложение не проверено»** остаётся при каждом согласии.
- **Отказ Google неотличим от отказа пользователя** (`access_denied`): MailExpert не распознаёт блокировку проекта или исчерпание лимита сам, приложение закрывает или отключает администратор.

## Нагрузка по правилам Gmail без настоящих ящиков

`scripts/deploy/test/e2e-mailcow.sh --scenario load --kind gmail --mailboxes 100 --panel-env IMAP_MAX_PERSISTENT_PER_HOST=15`
подключает к панели 100 ящиков как Gmail: IMAP `imap.gmail.com:993`, SMTP `smtp.gmail.com:587`. Внутри тестового
контейнера на эти имена отвечает свой DNS-сервер адресом тестового mailcow, поэтому панель применяет к ним свои
правила для Gmail (размер пула, фоновые соединения на хост, статус папок через пул, не больше 15 постоянных
соединений на хост, остальные ящики опрашиваются по таймеру). Перед нагрузкой скрипт проверяет, что оба имени
ведут на mailcow, и останавливается, если нет: панель ищет адрес почтового сервера через DNS, а не через
`/etc/hosts`, и без этого вошла бы в настоящий Gmail.
