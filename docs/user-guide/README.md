# Руководство пользователя MailExpert

MailExpert — веб-панель для общих почтовых ящиков на своём сервере: несколько сотрудников работают
с одними и теми же ящиками (Gmail, Microsoft 365, ящики собственного почтового узла, любые IMAP/SMTP)
в одном окне. Руководство описывает интерфейс по экранам: что делает каждое действие, кому оно
доступно и о чём важно помнить. Названия кнопок и вкладок приведены так, как их показывает
русский интерфейс.

Установка, обновление по SSH, почтовый узел и тенант Microsoft со стороны сервера — в
[руководстве по эксплуатации](../operations/README.md).

## 1. Роли

В MailExpert две роли:

| Роль | Что может |
|---|---|
| Пользователь | Читает, пишет и разбирает почту всех ящиков установки, добавляет ящики Gmail и ящики почтового узла, меняет оформление и общие поля ящиков, ведёт правила, чёрный список и контакты. Может удалить любой обычный ящик, запланировать удаление любого ящика почтового узла (и отменить его) и запустить у ящика «Переиндексировать для поиска» |
| Администратор | Всё то же, плюс настройки сервера ящиков, пользователи, интеграции, почтовый узел, журнал, обновление панели и остальные разделы «Администрирования» |

Главное правило: **ящики общие**. Каждый вошедший видит все ящики установки, их письма, правила,
чёрный список, контакты и письма в очереди отправки, кто бы их ни добавил. Ящик помнит только, кто
его добавил.

Разделы и поля, доступные только администратору, пользователю не показываются.

## 2. Вход

### 2.1. Вход через Google и Cloudflare Access

На установке с входом через Google экран называется «Вход в MailExpert»:

- если панель открыта через Cloudflare Access организации, пользователь уже вошёл и экрана не видит;
  без Access на экране написано «Откройте MailExpert по ссылке Cloudflare Access вашей организации.»;
- если включён вход через Google, кнопка «Войти через Google» пускает только Google-аккаунты,
  которые одобрил администратор (раздел 13.7). Чужой аккаунт получит «Этот Google-аккаунт не одобрен
  для MailExpert», отключённый пользователь — «Ваш доступ к MailExpert отключён.»

В этом режиме нет паролей, 2FA, резервной почты и SSO: всё это делает Google или Cloudflare.

### 2.2. Вход по имени и паролю

Рабочая установка входит через Google и Cloudflare Access (раздел 2.1). Вход по имени и паролю —
для установок с собственными учётными записями: экран показывает «Имя пользователя», «Пароль» и
«Войти».

- **Регистрация.** «Зарегистрироваться» работает, только если администратор открыл регистрацию; иначе
  нужна ссылка-приглашение (раздел 13.7). На странице приглашения видно «Приглашён как»; просроченная
  ссылка даёт «Эта ссылка-приглашение недействительна или срок её действия истёк.» Адрес, на который
  пришло приглашение, становится резервной почтой новой учётной записи.
- **Забыли пароль?** Введите резервный адрес почты, «Отправить ссылку», затем по ссылке из письма —
  «Установить новый пароль» (не короче 8 символов). Работает, если у учётной записи задана резервная
  почта, а сервер может отправлять письма («Системная почта», раздел 13.7).
- **SSO.** Кнопки «Войти через <провайдер>» появляются, если администратор добавил OIDC-провайдеров.
  Если вход с паролем отключён, экран называется «Войти через SSO», пишет «Вход с паролем отключён на
  этом сервере.» и показывает только кнопки «Войти через <провайдер>».

### 2.3. Двухфакторная аутентификация

2FA — необязательная защита уровня администратора: только при входе по паролю, политику задаёт
администратор (раздел 13.3). Что видно после верного пароля:

- **Доверенное устройство.** Если этот браузер уже запомнен и срок доверия не истёк, код не
  спрашивается вовсе.
- **Код из приложения.** Если у учётной записи включена 2FA (приложение-аутентификатор), всегда
  появляется «Двухфакторная аутентификация»: 6-значный код из приложения, «Проверить».
- **Код по почте.** Только если администратор включил «Требование MFA» = «Обязательно», у учётной
  записи нет приложения-аутентификатора, задана резервная почта и сервер смог отправить письмо:
  появляется «Проверьте почту», код приходит на резервный адрес, «Отправить повторно» шлёт новый.
- **Настройка 2FA.** Если MFA обязательна, а кода по почте нет (нет резервной почты или системная
  почта не работает), вход ведёт на «Настройка двухфакторной аутентификации»: «Сканировать QR-код»
  (или ключ вручную), затем код и «Включить 2FA и войти».
- **«Запомнить это устройство».** Галочка на шаге кода есть, только если администратор разрешил
  доверие устройству («Срок доверия устройству» не «Никогда»): тогда повторный запрос 2FA на этом
  браузере отключается на заданный срок (7 дней, 30 дней или навсегда).

### 2.4. Блокировка экрана

PIN-блокировка — тоже необязательная защита уровня администратора. Если у учётной записи задан
PIN-код, в меню пользователя есть «Заблокировать». Экран блокировки просит PIN («Разблокировать»)
или предлагает «Выйти».

PIN, 2FA и резервную почту настраивает администратор во вкладке «Безопасность», которая видна
только администраторам (раздел 13.3). Резервной почтой пользователя по умолчанию становится адрес,
на который пришло приглашение (раздел 2.2).

### 2.5. Профиль и язык

Меню пользователя (внизу боковой панели) → «Редактировать профиль»: «Отображаемое имя» (вместо имени
пользователя) и фото. При первом входе MailExpert предлагает выбрать язык интерфейса; потом он
меняется в «Внешний вид → Язык и шрифт».

## 3. Главный экран

Экран состоит из боковой панели с ящиками и папками, списка писем и области чтения. Расположение
областей меняется в «Внешний вид → Макет»; правая боковая панель (GTD) переключается `Ctrl+/`.
На телефоне боковая панель
открывается кнопкой «Меню», список обновляется жестом «Потяните для синхронизации».

## 4. Боковая панель

### 4.1. Верхние пункты

| Пункт | Что делает |
|---|---|
| «Написать» | Открывает редактор нового письма |
| «Входящие по всем» | Общая лента входящих всех включённых ящиков; счётчик — непрочитанные по всем ним |
| «Контакты» | Адресная книга (раздел 9) |
| «Запланированные» | Письма, ждущие отправки (раздел 8). Пункт виден, только пока такие письма есть; если какое-то не ушло, он называется «Запланированные · N не отправлено» (для нескольких писем — «… не отправлены») |

Число непрочитанных бледнеет, если это последнее известное значение и панель ждёт обновления с
сервера.

### 4.2. Список ящиков

- **Поиск.** Поле «Найти ящик…» сужает список по имени и адресу ящика. Оно только скрывает строки:
  выбор, счётчики и сами ящики не меняются.
- **Закрепление.** Меню ящика (правый клик) → «Закрепить» / «Открепить». Закреплённые ящики всегда
  наверху, в порядке закрепления, со значком «Закреплён».
- **Порядок.** По умолчанию незакреплённые ящики идут по дате последнего полученного письма, новые
  сверху («Сортировать аккаунты по последнему письму» в «Внешний вид → Макет»). Если сортировку
  выключить, порядок задаётся вручную пунктами меню «Переместить вверх» / «Переместить вниз». Для
  закреплённых эти пункты меняют порядок закрепления.
- **Состояние подключения.** Значок у ящика показывает:

| Состояние | Подсказка |
|---|---|
| Всё в порядке | «Подключён, синхронизация идёт» |
| Давно нет синхронизации | «Нет синхронизации последние 15 минут» |
| Ошибка | «Ошибка синхронизации» (под именем — «Ошибка подключения») |
| Нужен новый вход | «Вход истёк, нужно подключить заново» |
| Выключен | «Ящик отключён» |

- **Переподключить.** У ящика Gmail, которому нужен новый вход, прямо в строке есть кнопка
  «Подключиться заново»: она открывает окно Google. Войти нужно в ту же учётную запись, к которой
  привязан ящик. Тот же пункт есть в меню ящика; у ящика с паролем он просто запускает новое
  подключение. Переподключать может любой пользователь. Ящики почтового узла подключаются
  автоматически и переподключения не требуют; ящик Microsoft, подключённый вручную, — забота
  администратора (раздел 13.4): если ему нужен новый вход, сообщите администратору.
- **Пометки под именем.** «Будет удалён <дата>» — удаление ящика почтового узла запланировано
  (раздел 12.1); «Ждёт тенант: почта на него пока отклоняется» — новый ящик узла ещё не заведён в
  тенанте Microsoft.

Меню ящика целиком: «Новая папка», «Отметить все как прочитанные», «Синхронизировать сейчас»,
«Синхронизировать папки сейчас», «Закрепить», «Переместить вверх/вниз», «Настройки аккаунта»,
«Подключиться заново».

### 4.3. Папки

Ящик раскрывается в дерево папок. Меню папки: «Отметить все как прочитанные», «Синхронизировать
папку», «Переименовать», «Создать подпапку», «Скрыть папку» / «Показать папку», «Добавить в избранное»,
«Очистить папку», «Удалить папку». Порядок папок меняется перетаскиванием.

- Избранные папки собраны в разделе «Избранное» наверху; их можно переименовать для себя
  («Переименовать избранное»).
- Скрытые папки сворачиваются в строку «N скрытых папок».
- **Осторожно:** «Очистить папку» и «Удалить папку» удаляют письма безвозвратно, мимо корзины.

### 4.4. Меню пользователя

Внизу боковой панели: «Редактировать профиль», «Добавить аккаунт», «Настройки», «Заблокировать»
(только при заданном PIN), «Выйти». Переключатель «Блокировать изображения» включает и выключает
загрузку удалённых картинок в письмах. Если доступна новая версия, там же появляется «Доступно
обновление: v<версия>».

## 5. Список писем

### 5.1. Над списком

- **Поиск** — поле «Поиск…» (раздел 10).
- **Непрочитанные** — переключатель «Только непрочитанные» / «Показать все».
- **Синхронизировать** — «Синхронизировать этот аккаунт» в ящике, «Синхронизировать все аккаунты»
  во «Входящих по всем».
- **Счётчик писем** показывает, откуда число: «Писем на почтовом сервере», «Письма из кэша,
  подходящие под фильтр» или «Последнее известное число писем; ждём обновления от сервера».

### 5.2. Вкладки категорий

Если администратор включил категоризацию (раздел 13.1), входящие делятся на вкладки «Основные»,
«Рассылки», «Акции», «Автоматические», «Соцсети». Категорию письма можно поменять вручную:
контекстное меню → «Категоризировать как…». Письмо без категории предлагает «Классифицировать с ИИ»,
если включён ИИ-ассистент.

### 5.3. Выбор и массовые действия

Флажок у строки (или клавиша `x`, или «Выбрать» в контекстном меню) выбирает письмо; «Выбрать все» —
всю страницу. Над списком появляется «Выбрано: N» и действия:

| Действие | Что делает |
|---|---|
| «Отметить звездой» / «Убрать звезду» | Звезда у всех выбранных |
| «Отметить как прочитанное» / «Отметить как непрочитанное» | Статус прочтения |
| «Архивировать выбранные» | Перенос в папку архива ящика |
| «Удалить выбранные» | Перенос в корзину |
| «Переместить» | Перенос в папку; доступно, только если все выбранные письма из одного ящика |
| «Очистить выбор» | Снимает выделение |

Архивирование требует папки архива в «Сопоставлении папок» ящика (раздел 12.1); без неё панель
пишет «Нет папки архива».

### 5.4. Контекстное меню письма

Правый клик по строке: «Открыть», «Открыть в новом окне», «Отметить как прочитанное», «Пометить
сообщение звездой», «Ответить», «Ответить всем», «Переслать», «Переместить» (с недавними,
избранными и поиском по папкам), «Архивировать», «Отложить», «Категоризировать как…», «Создать
правило из сообщения», «Добавить в чёрный список», «Пометить как спам» / «Пометить как не спам»,
«Копировать тему», «Копировать адрес отправителя», «Копировать ссылку», «Показать полные заголовки»,
«Удалить».

### 5.5. Быстрые действия и смахивание

- При наведении на строку появляются значки быстрых действий, если они включены («Быстрые действия
  при наведении» в «Внешний вид → Макет»). Набор выбирается там же: прочитано, звезда, архив,
  «Отложить», удалить, «Переместить».
- На сенсорном экране письмо смахивается влево и вправо; действие каждого направления задаётся в
  «Действия смахивания».

### 5.6. Отложить

«Отложить» убирает письмо (вместе с его цепочкой в этой папке) в папку `Snoozed` ящика и возвращает
его в исходную папку в назначенное время: «Через 3 часа», «Завтра утром», «На следующей неделе»,
«Другое...». Письмо без заголовка Message-ID отложить нельзя.

### 5.7. Спам

«Пометить как спам» (в окне письма — «В спам») переносит письмо в папку спама ящика, «Пометить как
не спам» («Не спам») — во входящие. Если сервер отказал, появляется «Не удалось пометить как спам»
и письмо остаётся на месте. Как открываются письма из «Спама» — раздел 6.2.

### 5.8. Отмена действий

После архивирования, удаления, перемещения или пометки спама несколько секунд висит уведомление
с кнопкой «Отменить»; то же делает `Ctrl+Z`, пока уведомление на экране. Если перемещение на сервере
не удалось, письмо возвращается само: «Письмо возвращено в папку <папка>».

### 5.9. Заметка о простое почтового узла

Если почтовый узел какое-то время не принимал почту, над списком писем затронутого ящика появляется
«Письма вам, задержанные или потерянные, пока почтовый узел не работал». «Показать письма» раскрывает
таблицу (от кого, кому, тема, когда получено, состояние):

| Состояние | Подсказка панели |
|---|---|
| «Ещё ждёт в очереди Microsoft» | «Придёт само, когда почтовый сервер снова заработает.» и сколько осталось до конца попыток Microsoft |
| «Не доставлено: отправитель получил уведомление о недоставке» | «Попросите отправителя прислать письмо ещё раз.» |
| «Не доставлено: Microsoft прекратил попытки через 24 часа, отправитель получил уведомление о недоставке» | «Попросите отправителя прислать письмо ещё раз.» |
| «Пришло с опозданием» | — |
| «Задержано спам-фильтром Microsoft» | — |

«Понятно» прячет заметку в этом браузере, пока не появится новое задержанное письмо или у уже
показанного не сменится состояние.

## 6. Окно письма

### 6.1. Панель действий

«Ответить», «Ответить всем», «Переслать», «В архив», «Переместить», «Удалить», «В спам» / «Не спам»,
«Отметить», «Непрочитанное», «Заголовки», «Печать», «Скачать .eml», «ИИ» и, при подключённом Todoist,
«Задача». Стрелки «Предыдущее сообщение» / «Следующее сообщение» листают список.

Над текстом письма видно «Пришло в ящик» или «Отправлено из ящика» — какой из общих ящиков получил
или отправил письмо и на какой адрес.

Прочее в окне письма:

- **Удалённые изображения** по умолчанию заблокированы: «Загрузить изображения», «Всегда разрешать от
  <адрес>», «Всегда разрешать от @<домен>».
- **Вложения** скачиваются по одному или «Скачать все». Опасные типы помечены: исполняемые файлы —
  «Опасный тип файла», документы с макросами и HTML — «Рискованный тип файла», архивы — «Архив —
  содержимое невозможно проверить», двойное расширение — «Скрытое расширение». Опасный и рискованный
  файл (в том числе со скрытым расширением) скачивается только повторным нажатием; архив скачивается
  сразу. «Скачать все» тоже переспрашивает, если среди файлов есть опасный или рискованный.
- **Отписаться** — у рассылок со ссылкой отписки.
- **История отправителя** — «Раньше с <адрес>: N писем», «Найти все письма от него», «Вся цепочка»
  (все письма переписки ниже).
- **ИИ**: «Резюмировать» и собственные «ИИ-действия», если администратор включил ИИ (раздел 13.5).
- **Поиск по тексту письма** — «Найти» в контекстном меню, с «Учитывать регистр».
- **Цепочка** — в окне «Полные заголовки» («Заголовки» на панели или «Показать полные заголовки» в
  контекстном меню) есть блок «Цепочка»: почему письмо попало в эту цепочку (Message-ID, In-Reply-To,
  References, «Причина», «Режим ящика»).

### 6.2. Безопасный просмотр

Письмо в папке «Спам» ящика, а также письмо, которое Microsoft EOP отметил как фишинг или
вредоносное в любой папке, открывается в безопасном просмотре. Полоса сверху называет причину:
«Письмо в «Спаме»», «Похоже на фишинг», «В письме может быть вредоносное содержимое», «Отправитель
письма может быть подделан», и вердикт фильтра («Вердикт почтового фильтра: …»).

В безопасном просмотре:

- показан только текст: без картинок и стилей, ссылки не кликаются, у каждой ссылки и формы видно,
  куда она ведёт («ссылка на», «форма отправляет на»);
- вложения не открываются: «Чтобы открыть вложения, покажите письмо полностью.»;
- ответ, пересылка и печать цитируют этот же безопасный текст;
- «Скачать .eml» сначала предупреждает, что файл содержит письмо целиком.

«Показать полностью» открывает письмо как обычно. Делайте это, только если уверены в отправителе.
Если EOP только предупреждает о возможной подделке отправителя, а письмо лежит не в «Спаме», показана
полоса-предупреждение, но письмо открыто полностью.

### 6.3. «Почему письмо в «Спаме»?»

У письма из «Спама» ящика почтового узла под полосой безопасного просмотра есть ссылка «Почему письмо
в «Спаме»?». Она доступна любому пользователю и ничего не меняет. Панель ищет письмо в недавней
истории спам-фильтра узла и отвечает словами, кто положил письмо в «Спам»:

- спам-фильтр почтового узла (rspamd) — с оценкой, порогами и символами;
- Microsoft EOP — с категорией;
- ни один фильтр — письмо перенёс человек, правило входящих или фильтр.

Если письмо старше просмотренной истории, ответ так и говорит. Подробности —
[mail-node.md, раздел 6в](../operations/mail-node.md).

### 6.4. Доставка

Под письмом, отправленным из ящика, и под письмом с пометкой о доставке есть раскрывающийся блок
«Доставка». Он доступен любому, кто может открыть письмо. Для письма, отправленного из этого ящика,
он показывает по каждому получателю состояние словами: «Принято следующим
сервером», «Принято Microsoft EOP», «Доставлено в ящик почтового узла», «Задерживается: почтовый узел
повторит попытку», «Не доставлено», «Итог неизвестен» и другие, с кодом и объяснением. Для ящика узла
видны также сервер, которому передано письмо, шифрование («Шифрование») и «Ответ сервера».

Важно:

- «Отправлено» в панели значит только, что почтовый сервер принял письмо. Блок «Доставка» отвечает на
  вопрос, дошло ли оно дальше.
- Отсутствие сведений не значит «доставлено»: блок прямо пишет, если лог узла письмо уже не покрывает.
- У письма, отправленного не из этого ящика, сведений по получателям нет: блок пишет «Это письмо
  отправлено не из этого ящика, поэтому сведений о доставке у него нет.»
- В списке писем у отправленного письма появляется пометка «Не доставлено» или «Доставка
  задерживается».

**Трассировка Microsoft.** Для письма, отправленного из ящика почтового узла, в блоке есть раздел
«В Microsoft (трассировка EOP)» и кнопка «Спросить трассировку Microsoft» («Спросить ещё раз» для
повтора). Она показывает, что Microsoft сделал с письмом после узла: доставил, не доставил, держит
в очереди, поместил в карантин, отфильтровал как спам. Ограничения:

- трассировка должна быть подключена администратором («Трассировка Microsoft не подключена.»);
- Microsoft показывает письма с опозданием 5-30 минут и хранит трассировку 90 дней;
- только для писем, отправленных из этого ящика.

Подробнее — [mail-node.md, раздел 6г](../operations/mail-node.md).

## 7. Редактор

Редактор открывается кнопкой «Написать», ответом или пересылкой. Окно можно «Свернуть»,
«Развернуть» и «Закрыть».

### 7.1. Отправитель

- **«От».** Список адресов, с которых можно отправить: ящики установки и их алиасы. По умолчанию
  выбирается ящик, из которого пишете или на который пришло письмо; в общей ленте — «Отправитель по
  умолчанию» из «Внешний вид → Макет», иначе последний использованный ящик.
- **Имена отправителя.** У ящика есть «Имя отправителя» и, при желании, «Второе имя отправителя»
  (например, латиницей для зарубежных адресатов). Оба появляются в «От»: выберите нужное. Ответ по
  умолчанию уходит под основным именем.
- **Алиасы.** У обычного ящика алиас может иметь другой адрес и Reply-To. Ящик почтового узла
  отправляет только со своего адреса; старый алиас с другим адресом показан в «От» как «не ящик,
  отправка невозможна».

### 7.2. Письмо

- «Кому», «Копия», «Скрытая копия», «Тема». Правый клик по адресу: «Копировать адрес», «Копировать
  все в этом поле».
- «Приоритет»: «Высокий приоритет», «Обычный», «Низкий приоритет» (заголовки X-Priority и
  Importance).
- Форматирование, цвет, таблицы, ссылки, изображения — в панели инструментов; формат по умолчанию
  («Форматированный текст» или «Обычный текст») задаётся в «Внешний вид → Макет».
- «Подпись» ящика (или алиаса) добавляется в конец письма.
- «ИИ-ассистент»: «Написать черновик», «Улучшить», «Сократить», «Исправить грамматику» — если
  администратор включил ИИ.

### 7.3. Вложения и черновики

- «Прикрепить файл» добавляет вложение.
- Черновик сохраняется автоматически и кнопкой «Сохранить черновик»; при закрытии редактор спрашивает
  «Сохранить черновик?».
- **Вложения не сохраняются вместе с черновиком**: при повторном открытии черновика их нужно
  прикрепить заново.
- Перед отправкой редактор переспрашивает, если нет темы («Отправить без темы?») или текст упоминает
  вложение, а его нет («Забыли вложение?»).

### 7.4. Отправка и отмена отправки

«Отправить» (`Ctrl+Enter`) не отправляет письмо сразу: оно 5 секунд ждёт на сервере. Пока на экране
уведомление, «Отменить отправку» возвращает письмо в редактор таким, каким оно было. Потом остановить
письмо уже нельзя («Письмо уже отправляется, остановить его нельзя.»).

Если редактор с другим письмом в этот момент открыт, возвращённое письмо откроется, когда его
закроют («Письмо сохранено»).

После отправки появляется «Сообщение отправлено» с кнопкой «Просмотреть». «Отправлено, но не
сохранено в папке Отправленные» значит, что письмо ушло, но копию в «Отправленных» сделать не удалось.

### 7.5. Отправить позже

Стрелка рядом с «Отправить» → «Отправить позже»:

| Вариант | Время (по часам браузера) |
|---|---|
| «Сегодня вечером» | 18:00, предлагается, пока до него не меньше часа |
| «Завтра утром» | 8:00 следующего дня |
| «В понедельник утром» | 8:00 ближайшего понедельника; не предлагается, если завтра понедельник |
| «Выбрать дату и время…» | Любое время в будущем, не дальше года вперёд |

Запланированное письмо попадает в «Запланированные» (раздел 8). Механика очереди —
[job-queue.md](../architecture/job-queue.md), раздел «Отправка через очередь».

### 7.6. Если письмо не ушло

Временные сбои (сервер недоступен, «попросил повторить позже») сервер повторяет сам. Окончательные
отказы оставляют письмо в «Запланированных» со статусом «Не отправлено». Отдельный случай —
«Соединение прервалось во время отправки»: письмо могло дойти, поэтому перед повторной отправкой
проверьте «Отправленные». У Gmail есть свои ответы: дневной лимит, слишком большое письмо, отклонённый
адрес, «Gmail отклонил доступ к этому аккаунту. Переподключите его…».

## 8. Запланированные

Пункт «Запланированные» в боковой панели открывает список писем, которые ждут отправки или не ушли.
Фильтр «Ящик» / «Все ящики».

| Статус | Значение |
|---|---|
| «Сейчас уйдёт» | Письмо в 5-секундном окне отмены |
| «Запланировано» | Ждёт своего времени |
| «Будет повторено» | Временный сбой, сервер повторит |
| «Отправляется» | Уже уходит, остановить нельзя |
| «Не отправлено» | Окончательный отказ |
| «Требует внимания» | Соединение прервалось во время отправки, письмо могло дойти |
| «Отправлено» | Почтовый сервер принял письмо, но отметить его как отправленное не удалось. Отправлять повторно не нужно: осталось только «Удалить» запись |

Действия: «Изменить», «Изменить время», «Отменить отправку», «Отправить снова», «Удалить».
«Изменить» открывает письмо в редакторе с его временем: кнопка отправки показывает «Отправить
<время>», а меню рядом с ней — «Отправить сейчас».

**Кто что может.** Ящики общие, поэтому список видят все пользователи (без скрытых копий). Менять,
переносить, отменять и отправлять снова может только автор письма и администратор. Неотправленное
письмо хранится до указанной даты («Хранится до <дата>, затем будет удалено»). При входе пользователь
видит уведомление, если его письма не ушли, пока его не было.

## 9. Контакты

«Контакты» в боковой панели — общая адресная книга установки: каждый пользователь видит и может
изменить любой контакт.

- «Новый» → «Новый контакт»: отображаемое имя, имя, фамилия, email, телефон, сайт, организация,
  заметки.
- Контакты с меткой «auto» («Обнаружен из входящей почты») MailExpert добавляет сам из входящей почты.
- У контакта видно «Получено писем» и «Отправлено писем»; «Показать письма» раскрывает переписку.
- «Написать» открывает редактор с адресом контакта.

## 10. Поиск

Поле «Поиск…» над списком ищет в текущем ящике и папке; во «Входящих по всем» — по всем ящикам.
Подсказка «Операторы поиска» под полем перечисляет операторы:

| Оператор | Значение |
|---|---|
| `from:amazon` | От отправителя |
| `subject:invoice` | В теме |
| `to:john` | Кому / CC |
| `has:attachment` | Есть вложение |
| `is:unread` | Только непрочитанные |
| `is:starred` | Только отмеченные |
| `after:2024-01-01` | После даты |
| `before:2024-12-31` | До даты |
| `in:all` | Искать во всех папках |
| `-from:amazon` | Исключить (префикс `-`) |

Операторы сочетаются с обычными словами. Если поиск находит не все письма ящика, у него можно
запустить «Переиндексировать для поиска» в «Аккаунтах»: это может сделать любой пользователь.

## 11. Горячие клавиши и палитра команд

Клавиша `?` показывает справку «Горячие клавиши». Сочетания по умолчанию:

| Клавиша | Действие |
|---|---|
| `c` | Написать |
| `/` | Поиск |
| `?` | Показать горячие клавиши |
| `j` / `k` | Следующее / предыдущее сообщение |
| `o` | Открыть первое сообщение |
| `g`, затем `i` | Перейти во входящие |
| `Ctrl+/` | Переключить правую боковую панель |
| `r` / `a` / `f` | Ответить / ответить всем / переслать |
| `e` | Архивировать |
| `#` | Удалить |
| `s` | Пометить звездой |
| `m` | Прочитано / не прочитано |
| `x` | Выбрать сообщение |
| `Ctrl+Z` | Отменить последнее действие |
| `Ctrl+P` | Печать |
| `t` / `w` / `d` | GTD: «Задачи» / «Наблюдение» / «Делегировано» (если GTD включён) |

Переназначить их можно в «Настройки → Горячие клавиши» (на телефоне вкладки нет).

**Палитра команд** — `Ctrl+K` (`Cmd+K` на Mac), поле «Поиск действий…»: «Написать новое сообщение»,

темы», переключение темы, «Тема как в системе». У администратора есть и «Открыть почтовый узел».

## 12. Настройки: разделы для всех

«Настройки» открываются из меню пользователя. Слева — вкладки по группам («Аккаунт и почта»,
«Отображение», «Безопасность и интеграции», «Администрирование»), сверху — «Поиск настроек…».
Пользователь без прав администратора видит только «Аккаунты», «Уведомления», «Правила», «Внешний вид»
и «Горячие клавиши» (на телефоне вкладки «Горячие клавиши» нет). Остальные вкладки описаны в
разделах 13 и 14.

### 12.1. Аккаунты

Вкладка «Почтовые аккаунты»: список всех ящиков установки с поиском «Поиск по адресу, имени, алиасу
или провайдеру…».

**Добавить аккаунт.** Способы:

| Способ | Кто | Как |
|---|---|---|
| «Gmail» | Все | Адрес Gmail → «Продолжить через Google» → вход и согласие в Google. Пароль MailExpert не видит |
| «Наш ящик» | Все | Ящик на домене собственного почтового узла: MailExpert создаёт его на узле и подключает, пароль не нужен |
| «Другой сервер» | Только администратор | Ручной ввод IMAP и SMTP |
| Microsoft 365 / Outlook.com | Только администратор | Необязательный ручной путь через «Интеграции» (раздел 13.4) |

Про Gmail:

- подсказка под полем показывает уже известные адреса: «Уже подключено», «Нужно переподключить»
  (с кнопкой «Переподключить»), «Отключён в настройках», «Подключался раньше»;
- если вкладка Google не открылась, используйте ссылку «Открыть страницу Google»: она одноразовая и
  живёт не дольше минуты;
- Google покажет экран «Приложение не проверено» — это ожидаемо, см.
  [google-oauth.md](../operations/google-oauth.md);
- «Имя отправителя» можно не заполнять: тогда письма уйдут под именем из профиля Google.

Про «Наш ящик»: адрес из имени и домена узла, «Название в списке ящиков (необязательно)», «Имя
отправителя» (обязательно) и «Второе имя отправителя (необязательно)», затем «Далее» и «Создать
ящик». Домен должен пройти подключение у администратора; если почтовый узел не настроен, вариант
неактивен с подсказкой «Почтовый узел ещё не настроен: обратитесь к администратору.» Удалённый ящик
стирается на узле вместе с письмами: если адрес удаляли раньше, он будет создан пустым.

Новый ящик сразу появляется у всех пользователей.

**Редактировать аккаунт.** Кто какие поля меняет:

| Поле | Пользователь | Администратор |
|---|---|---|
| «Отображаемое имя», «Цвет аккаунта», «Имя отправителя», «Подпись» | да | да |
| «Алиасы», «Сопоставление папок» | да | да |
| «Включить категоризацию входящих» (если не включена глобально) | да | да |
| Настройки IMAP и SMTP: серверы, порты, шифрование, «Пропустить проверку TLS-сертификата», логин и пароль, отдельные логин и пароль SMTP | нет | да |
| «Режим группировки цепочек» («Предпросмотр», «Пересчитать») | нет | да |
| «Сбросить привязку OAuth» (ящики Google и Microsoft) | нет | да |

Пользователь видит в форме «Настройки сервера этого ящика (серверы, порты, шифрование, вход) меняет
администратор.» Попытка поменять их всё равно будет отклонена сервером.

У ящика почтового узла сервер и пароль не меняет никто: «Этот ящик находится на почтовом узле:
сервер и пароль берутся из настроек узла, здесь их изменить нельзя.»

Переключателя «включить / выключить ящик» в интерфейсе нет: ящик выключается только через API.
Ящик почтового узла не выключается и через API — только удаляется.

**Алиасы.** «Добавить алиас»: «Отображаемое имя», адрес, «Reply-To (необязательно)», своя подпись.
Алиас отправляет через SMTP ящика. У ящика почтового узла вместо этого «Добавить имя отправителя»:
только другое имя для того же адреса. Другой адрес на узле — это отдельный ящик («Наш ящик»).

**Сопоставление папок.** Какая папка ящика служит «Отправленными», «Черновиками», «Корзиной»,
«Спамом / нежелательной почтой» и «Архивом». «Автоопределение» берёт папку по её роли на сервере.
Без папки архива не работает «Архивировать».

**Прочее у ящика:** «Переиндексировать для поиска», «Синхронизировать папки», «Последняя
синхронизация», ход загрузки номеров цепочек Gmail.

**Удаление.** Любой пользователь может удалить любой обычный ящик и запланировать удаление любого
ящика почтового узла.

- Обычный ящик: «Удалить ящик?» — ящик и все его синхронизированные письма пропадут у всех
  пользователей; отменить нельзя. Сами письма на почтовом сервере остаются.
- Ящик почтового узла удаляется с задержкой. Нужно ввести адрес ящика целиком и причину («Почему
  удаляется? (обязательно, сохраняется в журнале)»), затем «Запланировать удаление». Ящик продолжает
  работать указанное администратором число дней (по умолчанию 5), затем удаляется на узле
  **навсегда вместе с почтой**; если этот адрес потом добавить снова, ящик будет создан пустым.
  Подтверждение перечисляет псевдонимы узла, которые удалятся или
  перестанут доставлять в ящик. До даты у ящика видно «Ожидает удаления: будет удалён <дата>» с
  причиной и автором, и любой пользователь может нажать «Отменить удаление».

**Карантин узла для пользователей.** Если администратор разрешил («Пользователи видят записи ящиков
узла этой панели»), внизу «Аккаунтов» виден карантин почтового узла: письма в ящики узла, которые
спам-фильтр отклонил или пометил как спам. Только просмотр; выпускает письма администратор
(раздел 14.9).

### 12.2. Уведомления

- Звук новой почты: встроенные варианты, «Нет» или «Свой» (аудиофайл до 2 МБ).
- «Значки непрочитанных»: «Значок на иконке приложения» (PWA) и «Значок на вкладке браузера».
- «Push-уведомления»: «Включить» / «Отключить». Работают, если сервер настроен (иначе «Push-уведомления
  не настроены на этом сервере»); на iOS сначала добавьте MailExpert на экран «Домой».

### 12.3. Правила

Вкладка «Правила» состоит из «Правила» и «Чёрный список».

**Правила входящих** автоматически разбирают новую почту ящика.

- «Новое правило»: «Название правила», «Применять к» (ящик), «Совпадает» — все условия (И) или любое
  (ИЛИ).
- Условия: «От», «Кому», «Тема», «Тело письма», «Заголовок» (с именем заголовка), «Есть вложение»,
  «Статус прочтения»; операторы «содержит», «не содержит», «равно», «начинается с», «заканчивается на»,
  «соответствует регулярному выражению».
- Действия: «Отметить как прочитанное», «Отметить звездой», «Архивировать», «Переместить в корзину»,
  «Переместить в папку», «Переслать на» (один адрес).
- «Остановить обработку следующих правил при совпадении».
- «Применить правила к входящим» прогоняет правила по уже лежащим письмам в фоне; по окончании
  приходит уведомление.

Оговорки: условие по телу письма срабатывает, только если тело уже загружено; «Статус прочтения»
полезен в основном при ручном прогоне.

**Кто видит и меняет.** Правила общие, как и ящики: каждый пользователь видит правила всех ящиков,
может создать, изменить и удалить любое правило, кто бы его ни создал. У каждого правила показаны
автор («Автор: …») и адрес пересылки («Пересылает на …»), чтобы пересылку чужой почты нельзя было
спрятать. Создание, изменение (с адресом пересылки до и после), удаление и ручной запуск правил
записываются в журнал, который видит администратор.

**Чёрный список.** Адрес → «Заблокировать» для выбранного ящика; письма от него автоматически уходят
в корзину. Список тоже общий. Быстрый способ — «Добавить в чёрный список» в контекстном меню письма.

### 12.4. Внешний вид

Три подвкладки:

- **«Тема»**: цветовые темы и «Как в системе».
- **«Макет»**: расположение областей; «Сортировать аккаунты по последнему письму»; «Список
  сообщений» — «Бесконечная прокрутка» или «Постранично», число писем, «Быстрые действия при
  наведении», «Просмотр сообщений» (строка превью), «Аватары Gravatar» (передаёт хешированные адреса
  стороннему сервису), «Аватары отправителя (моб.)», «Фавиконы отправителей» (передаётся только
  домен), «Действия смахивания»; «Группировка переписки»; «Формат создания письма»; «Отправитель по
  умолчанию»; «Действие ответа по умолчанию»; «Отметить как прочитанное» — «Немедленно», «С задержкой»
  или «Вручную»; «Почтовое приложение по умолчанию» → «Зарегистрировать MailExpert» для ссылок mailto:.
- **«Язык и шрифт»**: язык интерфейса, «Типографика», «Размер шрифта» (по умолчанию 110 %),
  «Пользовательский CSS».

Эти настройки личные: они не меняют вид панели у других пользователей.

### 12.5. Горячие клавиши

Нажмите на сочетание, чтобы назначить новое (Esc отменяет запись). Если клавиша уже занята, панель
переназначит её и скажет об этом. У каждого действия есть «Удалить сочетание» и «Сбросить по
умолчанию»; для всех сразу — «Сбросить всё по умолчанию». На телефоне этой вкладки нет.

## 13. Настройки администратора

Все вкладки этого раздела видит только администратор. Пользователь, открывший ссылку на такую
вкладку, попадает в «Аккаунты».

### 13.1. Категории

- «Включить категоризацию глобально» включает вкладки категорий для всех ящиков и общей ленты; без
  неё категоризация включается у каждого ящика отдельно.
- «Источники для соцсетей»: домены и адреса для категории «Соцсети», вручную или подпиской на список
  по URL («Подписаться»), «Обновить».
- «Перекатегоризировать письма» для выбранного ящика.
- Подвкладка «GTD» (если плагин GTD включён) — раздел 15.

### 13.2. Очистка

«Очистка почтового ящика» (бета): доля массовых рассылок во входящих выбранного ящика, «Основные
массовые отправители» с кнопками «В архив» (рекомендуется) или «В Корзину», «Частые рекламные слова»
для поиска. Действие над отправителем касается всех его писем во входящих; из корзины их можно
восстановить, пока она не очищена.

### 13.3. Безопасность и конфиденциальность

PIN, 2FA и резервная почта — необязательная защита уровня администратора: политику для всех задаёт
администратор здесь, отдельной настройки для пользователя нет. Основной вход рабочей установки —
через Google и Cloudflare Access, и тогда блоки с пометкой «только вход по паролю» не показываются.

**«Безопасность»:**

| Блок | Что настраивает | Режим входа |
|---|---|---|
| «Блокировка экрана» | Свой PIN-код (4–6 цифр) и «Автоблокировка» | любой |
| «Защита входа» | «Макс. попыток» и «Окно блокировки (минут)» по IP | только вход по паролю |
| «Политика подключения к почтовому серверу» | «Разрешить частные / локальные хосты», «Разрешить небезопасный TLS», «Разрешить нестандартные порты» | любой |
| «Синхронизация ящиков» | Как часто сервер синхронизирует все ящики (общая настройка) | любой |
| «Приложение-аутентификатор» | Своя 2FA: «Настроить», «Отключить» (по паролю) | только вход по паролю |
| «Требование MFA» и «Срок доверия устройству» | 2FA для всех: «По желанию» или «Обязательно»; доверие устройству: «Никогда», «7 дней», «30 дней», «Навсегда» | только вход по паролю |
| «Резервная почта» | Адрес для кода входа и сброса пароля | только вход по паролю |
| «Связанные SSO-аккаунты» | «Связать» / «Отвязать» свой аккаунт с провайдером SSO | только вход по паролю |
| «Активность входа» | Последние события входа всех пользователей | любой |

**«Конфиденциальность»:** «Блокировать удалённые изображения», «Разрешённые отправители» и
«Разрешённые домены», от которых картинки грузятся всегда.

### 13.4. Интеграции

Две подвкладки: «Почтовые провайдеры» и «Приложения».

**Google-приложения** — OAuth-приложения, через которые подключаются ящики Gmail. Без хотя бы одного
приложения Gmail подключить нельзя.

- «Callback-адрес»: общий для всех приложений, его регистрируют в OAuth-клиенте каждого приложения.
- «Добавить приложение»: «Импортировать JSON-файл» клиента из Google Cloud Console или ввод
  «Идентификатор клиента» и «Секрет клиента» вручную; «Лимит пользователей».
- Таблица: «Занято / лимит», «Ящиков», «Состояние» («Активно», «Заполнено», «Закрыто», «Отключено»).
  Действия: «Сделать активным», «Закрыть для новых ящиков», «Отключить» (ящики потребуют
  переподключения через другое приложение), удаление (только если к приложению не привязан ни один
  ящик).

Пошагово — [google-oauth.md](../operations/google-oauth.md).

**Microsoft 365 / Outlook.com** — необязательный ручной путь только для администратора: ящики
почтового узла подключаются автоматически через EOP, и для них это не нужно. OAuth2 для рабочих,
учебных и личных аккаунтов Microsoft.
«Идентификатор приложения (клиента)», «Идентификатор каталога (арендатора)», «Секрет клиента», «URI
перенаправления», «Сохранить конфигурацию», затем «Подключить аккаунт Microsoft». Без Redirect URI
работает «Подключить через код устройства». Вводите код устройства, только если сами начали этот вход:
тот, кому вы передадите код, подключит на ваше место свою учётную запись. Подробнее —
[microsoft-oauth.md](../operations/microsoft-oauth.md).

**Todoist** — «Личный токен API» → «Подключить». Токен хранится для каждой учётной записи отдельно:
кнопка «Задача» в окне письма появляется только у того, кто подключил свой токен. Она открывает
«Создать задачу Todoist» с названием, описанием, проектом, метками, приоритетом и сроком.

### 13.5. ИИ-ассистент и ИИ-действия

- **«ИИ-ассистент»**: «Включить функции ИИ»; «Способ подключения» — «Использовать API-ключ» (любой
  провайдер с OpenAI API: «Базовый URL API», «Ключ API», «Модель») или «Использовать подписку»
  («Провайдер подписки» — «ChatGPT Plus/Pro (Codex Subscription)», «Подключить ChatGPT», вход по
  одноразовому коду); «Функции» — «Помощник по написанию (черновики и улучшение)» и «Краткое
  изложение писем»; «Проверить подключение».
- **«ИИ-действия»**: свои действия с названием и промптом; они появляются в меню «ИИ» окна письма.
  Пункт «Управление действиями…» в этом меню видит только администратор.

### 13.6. Плагины

«Плагины» (бета) включают дополнительные функции, сейчас это GTD. Администратор включает плагины для
всех: включённый плагин появляется у каждого пользователя и добавляет свои настройки в другие вкладки
(«Настроить параметры в разделе …»).

### 13.7. Пользователи

Вкладка «Пользователи», подвкладка «Пользователи и приглашения». Её вид зависит от режима входа.

**Вход через Google.** Список Google-аккаунтов, которым разрешён вход: «Email для одобрения» →
«Одобрить». У каждого: «Сделать администратором» / «Убрать права администратора», «Отключить» /
«Включить», «Удалить пользователя». Метка «Из BOOTSTRAP_ADMIN_EMAILS» — администратор из настроек
сервера. Каждый вошедший пользователь работает со всеми ящиками.

Подвкладка «Синхронизация с Access» (только в этом режиме): MailExpert приводит Allow-политику
приложения Cloudflare Access в соответствие с одобренными пользователями. Нужны «ID аккаунта», «ID
приложения», «ID политики», «API-токен». Синхронизация работает в обе стороны: пользователя, чей адрес
MailExpert записал в политику, а в Cloudflare его оттуда убрали, MailExpert отключает (администраторы
из BOOTSTRAP_ADMIN_EMAILS не отключаются никогда). Прогон останавливается и ничего не меняет, если
отключил бы больше пользователей, чем разрешает ACCESS_SYNC_MAX_DISABLES в настройках сервера (по
умолчанию 10; 0 останавливает любой прогон, который отключил бы хоть кого-то), или больше половины
активных пользователей.

**Вход по паролю.**

- «Открытая регистрация»: «Регистрация открыта» (любой может зарегистрироваться) или «Регистрация
  закрыта» (только по приглашению).
- «Пригласить пользователя»: адрес → «Отправить приглашение». Ссылка одноразовая, действует 7 дней;
  письмо уходит через системную почту, без неё ссылку можно «Копировать ссылку» и передать вручную.
  «Ожидающие приглашения» можно «Отозвать». Адрес приглашения становится резервной почтой
  зарегистрированного по нему пользователя.
- У пользователя: «Сделать администратором» / «Убрать права администратора», «Отключить 2FA»,
  «Удалить пользователя» (безвозвратно).

**«Системная почта»**: отдельный SMTP-аккаунт для приглашений, сброса паролей и кодов входа;
«Проверить подключение».

### 13.8. SSO

Только при входе по паролю. «Единый вход (SSO)»: «+ Добавить SSO-провайдера» из шаблона или
«Custom» (любой OIDC-провайдер); «URL издателя», «Идентификатор клиента» и «Секрет клиента», «Разрешённые домены электронной
почты (через запятую, …)», «Режим подготовки аккаунтов» («Отключено», «Сопоставлять существующие»,
«Открыто»), «Клейм группы администратора» и «Значение группы администратора», «Выход из SSO
(RP-initiated)». Если группа администратора задана, права пересчитываются при каждом входе через
SSO: члены группы становятся администраторами, остальные права администратора теряют.
«Вход с паролем» можно отключить, если есть хотя бы один включённый провайдер и учётная запись
администратора, который отключает, привязана к SSO; тогда при недоступном провайдере понадобится
прямой доступ к базе данных, чтобы снова включить вход с паролем.

### 13.9. Журнал

«Журнал» — что пользователи делали с ящиками, письмами и пользователями, сначала новые. Фильтры: «С
даты», «По дату», ящик, пользователь, действие. В журнал попадают, среди прочего:

- ящики: добавлен, переподключён, удалён, изменены настройки подключения, включён и выключен,
  запланировано и отменено удаление (с причиной), сброшена привязка OAuth;
- письма: отправлено, поставлено в очередь, отправка отменена или перенесена, не отправлено,
  удалено (в корзину или навсегда), перемещение отменено;
- правила входящих: создано, изменено (с пересылкой до и после), удалено, запущено вручную;
- пользователи и права администратора, синхронизация с Access;
- почтовый узел, EOP и тенант: настройки, домены, DNS, очередь, оповещения, карантин, простои,
  трассировки;
- обновление панели.

### 13.10. Обновление панели

«Обновление панели» обновляет панель до опубликованной версии (`latest`). Обновиться можно только на
неё и только вперёд: опубликованная версия должна быть новее работающей.

- «Работает версия» и «Опубликованная версия» со ссылкой «Сравнить на GitHub» и числом новых
  изменений;
- «Проверить» — предпроверка до любых изменений; когда карточка открывается и есть новая версия,
  проверка запускается сама: «Проблемы», «Предупреждения», «Что делать дальше»,
  миграции базы данных и возможен ли автоматический откат;
- «Обновить» неактивна, пока проверка нашла проблемы («Проверка нашла проблемы: исправьте их и
  проверьте снова.»), идёт проверка или обновление, или новой версии нет;
- «Обновить» → «Обновить панель до <версия>?» → «Обновить панель». Сначала делается резервная копия,
  затем панель на несколько минут перезапускается; страница сама подхватит новую версию, иначе —
  «Перезагрузить страницу»;
- если миграции есть, неудачное обновление не откатится само: откат вручную по инструкции;
- «Последнее обновление»: состояние, сообщение сервера, последние строки журнала и где лежит
  полный журнал.

Если служба обновления на сервере не установлена, карточка пишет «Механизм обновления не установлен».
Если опубликованная версия — та, с которой сервер уже откатывался, обновиться до неё нельзя, пока не
опубликована более новая («С версии <версия> сервер уже откатывался; обновиться до неё нельзя…»).
Обновление по SSH — [README.md, раздел 9](../operations/README.md), откат — [раздел 10](../operations/README.md).

### 13.11. О приложении

Версия, сборки бэкенда и фронтенда, лицензия, ссылки. Здесь же «Создать отчёт диагностики»:
очищенный отчёт без адресов, имён, тем, содержимого писем, паролей и токенов («Скачать JSON» или
копирование).

## 14. Почтовый узел (администратор)

Вкладка «Почтовый узел» объединяет собственный почтовый сервер mailcow, его домены и ящики, связь с
Microsoft EOP и тенантом, эксплуатацию, простои и карантин. Всё на ней, кроме списка готовых доменов
в форме «Наш ящик», заметки о простое над списком писем и просмотра карантина в «Настройки >
Аккаунты» (если администратор его разрешил), доступно только администратору. Каждое
изменение пишется в журнал. Серверная сторона — [mail-node.md](../operations/mail-node.md).

### 14.1. Подключение узла

- «Имя почтового узла» (имя, не IP: по нему идут IMAP, SMTP и API), «Ключ API mailcow», «Квота нового
  ящика, МБ», «Ссылка для проверки диска (необязательно)», «Адреса панели для fail2ban», «Адрес узла
  (IPv4)» (для проверки DNS).
- «Сколько дней ящик работает после запроса на удаление» — от 1 до 90; новое значение действует
  только для удалений, запрошенных после изменения.
- «Проверить и сохранить» сохраняет, только если узел принял ключ. После этого у всех пользователей
  в «Добавить аккаунт» становится доступен «Наш ящик».
- «Диск с почтой» показывает заполнение; выше 85 % — «Освободите место или увеличьте диск.»

Подробно — [mail-node.md, раздел 5](../operations/mail-node.md).

### 14.2. Домены и подключение

Таблица «Домены»: домен, ящики («N из M»), состояние. «Новый домен» + «Лимит ящиков» → «Добавить
домен». Домен, созданный в mailcow вручную, нужно «Принять».

Домен проходит шаги подключения; «Подробно» раскрывает их:

| Состояние | Что сделано |
|---|---|
| «Создан на узле» | Домен есть на узле |
| «Узел настроен» | Relayhost на хост EOP, DKIM, лимиты отправки |
| «DNS в порядке» | SPF, DKIM, DMARC, запись подтверждения тенанта |
| «Подтверждён в тенанте» | Домен добавлен в тенант Microsoft и подтверждён |
| «Тип Internal Relay» | Accepted domain типа Internal Relay |
| «Коннектор готов» | Outbound connector доставляет почту домена на узел |
| «Готов» / «Готов, DBEB» | Можно создавать ящики |

Шаг подтверждается кнопкой «Сделано» (только следующий по порядку) или, если подключён исполнитель
тенанта, MailExpert делает его сам («делает MailExpert в тенанте»). «Отметить готовым» — для пилота
или стенда без тенанта. «Начать подключение заново» возвращает домен к первому шагу; ящики и почта
остаются. Если узел сообщает другое время создания домена, панель предлагает «Принять новое время» или
начать подключение заново.

**DNS.** «Проверить сейчас» у домена и «Проверить DNS сейчас: узел и все домены» сравнивают MX, SPF,
DKIM, DMARC, TXT тенанта, MTA-STS, а у узла — A, PTR, отсутствие AAAA и сертификат на порту 587.
Каждая ошибка объяснена словами и дана запись для публикации. «Значения для публикации» — то, что
панель пока не читает сама (ожидаемые MX, TXT тенанта, CNAME селекторов DKIM EOP).

**«Настройки узла»** — что панель ставит на узел (TLS, relayhost, fail2ban, DKIM, лимиты отправки,
forwarding hosts) с итогом по каждому пункту; «Применить настройки». «Применить правило раскладки
спама…» перезапускает Dovecot: все IMAP-сессии оборвутся, панель и почтовые программы переподключатся.

Подробно — [mail-node.md, раздел 6](../operations/mail-node.md).

### 14.3. Ящики узла

«Ящики, созданные MailExpert»: адрес, занято, квота, «Лимит отправки». Квоту и лимит отправки
(писем за секунду, минуту, час или день; «По умолчанию») меняет администратор прямо в таблице.
«Нет на почтовом узле» — ящик есть в панели, но пропал с узла.

### 14.4. Удаление ящика узла

Удаление ящика узла может запросить любой пользователь (раздел 12.1), с обязательной причиной и
отсрочкой. Пока срок не прошёл, ящик работает, и любой может «Отменить удаление». После срока
MailExpert удаляет ящик на узле вместе с почтой и убирает его получателя из тенанта; если шаг не
удался, у ящика видно «Пока не удалось удалить, повтор позже». Журнал хранит, кто, когда и почему
запросил удаление.

### 14.5. Алиасы с другим адресом

На узле каждый адрес — отдельный ящик, и ящик отправляет только со своего адреса. «Алиасы с другим
адресом» перечисляет оставшиеся от прежних версий алиасы с чужим адресом («Адрес», «Имя отправителя»,
«У ящика»). Для каждого: «Создать отдельный ящик» (подпись и Reply-To переходят к новому ящику, алиас
удаляется) или удалить алиас (на узле ничего не меняется). Пользователь видит у такого алиаса
пометку, что с него письма не отправляются.

### 14.6. Почта через EOP и тенант Microsoft

**«Почта через EOP»** — как почта узла идёт через Microsoft EOP:

- «Хост EOP (следующий узел для почты)», «TLS до хоста EOP», «Параметры политики TLS», «Имя в
  сертификате», «Кто подписывает DKIM» («mailcow (узел)» или «Только EOP»);
- «Лимит отправки каждого ящика без своего лимита, писем в час» — останавливает взломанный ящик
  раньше, чем он заблокирует общий коннектор;
- «Лимит внешних получателей тенанта (TERRL)», «Лицензии», «Дата создания тенанта» и полоса
  «Внешние получатели за 24 часа (бюджет TERRL)»: выше лимита EOP останавливает всю внешнюю почту
  тенанта;
- «Подключение к тенанту»: «ID тенанта», «Домен тенанта», «ID приложения (клиента)», «Отпечаток
  сертификата», «Outbound connector к узлу», «Внешний домен контактов DBEB».

**«Тенант Microsoft»** (если подключён исполнитель тенанта):

- «Сертификат приложения» и «Проверить подключение» (сертификат, Microsoft Graph, Exchange Online);
- «Заблокированные коннекторы» — проверка каждые 10 минут, «Проверить сейчас»;
- «Антиспам-политика» — MailExpert ставит действиям для спама, явного спама, фишинга и массовой рассылки
  «Переместить в нежелательную», чтобы письма попадали в «Спам» ящика, а не оставались в карантине;
  «Проверить и исправить»;
- «Коннекторы» — сравнение с эталоном, «Принять как эталон»;
- **«Спам и фишинг в карантине EOP»** — выпуск из карантина Microsoft: «Выпускать спам и фишинг из
  карантина в ящики узла» (по умолчанию включено, включение и выключение пишутся в журнал), «Выпустить
  сейчас», «Последние письма» с итогом. Выпущенные письма ложатся в «Спам» ящика и открываются в
  безопасном просмотре. Вредоносные и другие типы MailExpert не выпускает: их выпускают в портале
  Microsoft Defender.

У домена в подробностях — «В тенанте Microsoft»: подтверждение, тип accepted domain, коннектор, DKIM
EOP, получатели в тенанте, удержание на Internal Relay («Удерживать на Internal Relay» / «Разрешить
Authoritative»), «Перевести в Internal Relay», «Удалить контакты псевдонимов», «Выполнить шаги
тенанта сейчас».

Подробно — [mail-node.md, раздел 6е](../operations/mail-node.md) и
[требования к панели EOP](../architecture/mail-node-research/eop-panel-requirements.md).

### 14.7. Эксплуатация узла

**«Оповещения»** проверяются каждые пять минут: отказы EOP (заблокированный коннектор, атрибуция
тенанта, лимит TERRL), почта мимо EOP, копящаяся отложенная почта, сертификат узла, остановленные
контейнеры, бюджет TERRL от 80 %, письма в очереди EOP после простоя и оповещения тенанта.
«Проверить сейчас». «Адрес проверки оповещений (Healthchecks)» получает сигнал после каждой проверки;
пороги «Отложенных писем больше чем» и «Самое старое отложенное старше (минут)» (по умолчанию 20 писем,
60 минут).

**«Очередь почты»** — письма, которые узел ещё не доставил: «В очереди N: отложено, задержано, в
работе». «Повторить все сейчас»; у письма — «Задержать», «Отпустить», «Отправить сейчас», «Удалить»
(безвозвратно, с подтверждением), «Показать текст письма». Каждое действие пишется в журнал, чтение
текста — тоже.

Подробно — [mail-node.md, раздел 6б](../operations/mail-node.md).

### 14.8. Простои

«Простои почтового узла» — периоды, когда узел не принимал почту от EOP, и письма, которые за это
время ждали в очереди EOP. EOP держит такие письма до 24 часов, затем возвращает отправителю.

- Баннер показывает, сколько писем ещё ждёт и когда EOP вернёт первое. Верните узел до этого времени
  и **не нажимайте «Fix now» в оповещении EAC**: EOP сразу откажет письмам из очереди.
- «Отметить период» — для планового обслуживания («Плановое обслуживание») или простоя, которого
  панель не заметила; «Закрыть», «Изменить», «Удалить» требуют причины.
- «Проверить трассировку сейчас» — не чаще раза в две минуты. Без подключённой трассировки панель
  показывает периоды, но не письма.
- «Письма» у периода: что стало с каждым письмом («пришло с опозданием», «не доставлено», «ещё ждёт»,
  «отфильтровано EOP»). Сотрудники видят свои письма в заметке над списком (раздел 5.9).
- «Хранить письма (дней)» — от 1 до 90, по умолчанию 30.

Подробно — [mail-node.md, раздел 6д](../operations/mail-node.md).

### 14.9. Карантин

«Карантин почтового узла» — письма, которые спам-фильтр узла (rspamd) отклонил или пометил как
спам. Фильтр по отправителю, получателю и теме; запись открывается в безопасном виде (без картинок и
кликабельных ссылок, вложения не открываются).

| Действие | Что происходит |
|---|---|
| «Выпустить» | Письмо доставляется в ящик мимо спам-фильтра, а rspamd запоминает его как не спам. Отменить нельзя. Если письмо отметил и EOP, правило раскладки снова положит его в «Спам» |
| «Удалить и обучить как спам» | Копия удаляется безвозвратно, rspamd запоминает письмо как спам |
| «Удалить» | Копия удаляется безвозвратно |

- «Включить карантин на этом узле» записывает все настройки карантина mailcow, заменяя ручные.
- Галочка «Пользователи видят записи ящиков узла этой панели» открывает пользователям просмотр
  карантина (раздел 12.1). Выпуск и удаление остаются за администраторами.

Подробно — [mail-node.md, раздел 6в](../operations/mail-node.md).

## 15. GTD

GTD — плагин, который превращает почту в список дел. Администратор включает его для всех в «Плагины»
(раздел 13.6), затем в «Категории → GTD» GTD включают для каждого ящика и сопоставляют состояния с папками IMAP («Создать
недостающие папки»).

- Состояния: «Задачи», «Наблюдение», «Делегировано», «Когда-нибудь», «Справочное». Метка ставится
  клавишами `t`, `w`, `d` или через пункт «GTD» в контекстном меню; там же «Убрать из …».
- Правая боковая панель (`Ctrl+/`) показывает разделы GTD и «Ожидает»; «Отметить выполненным»
  снимает метки, отмечает письмо прочитанным и архивирует его из входящих.
- Пустые входящие показывают питомца «Входящие — ноль»; своего можно загрузить в настройках GTD
  (pet.json и спрайт-лист).
